# AI Coding 实践分享（按 Slide 拆分）

## 使用规范
- 每一页均按以下结构编写：第几页、提示词、解释、重点描述。
- 提示词用于 AI 生成该页内容，可直接复制给生成工具。
- 解释用于你自己讲解时把控节奏，不放到页面正文。

## 第 1 页：封面
提示词：
生成一页企业内部技术分享封面页，主题是“AI Coding 实践分享：从尝鲜到稳定落地”，副标题“基于 GitHub Copilot 企业版的真实经验”。风格专业、简洁、偏工程团队气质。包含演讲者姓名、部门、日期。避免过于花哨的装饰。

解释：
建立正式感与可信度，让同事知道这是实战经验分享，不是概念科普。

重点描述：
- 标题：AI Coding 实践分享
- 副标题：从尝鲜到稳定落地
- 关键信息：基于 GitHub Copilot 企业版

## 第 2 页：使用前说明（必讲）
提示词：
生成一页“使用前说明”幻灯片，三条信息必须完整展示：1）公司目前已支持 GitHub Copilot 企业版；2）申请地址为 https://siemens.sharepoint.com/sites/devboost/SitePages/Getting-Started.aspx ；3）本次分享后续经验与实操均基于 GitHub Copilot 平台。版式清晰，链接可读。

解释：
先统一入口和平台，避免听众后面问“工具在哪申请、和你是不是同一套环境”。

重点描述：
- 公司已支持 GitHub Copilot 企业版
- 申请地址已给出
- 本次内容全部基于 GitHub Copilot

## 第 3 页：今天你将获得什么
提示词：
生成一页“学习目标”页面，面向研发同事。列出三项收益：1）知道 AI Coding 适用与不适用场景；2）掌握一套可复用的人机协作流程；3）拿到可直接用的提示词模板。每项配一句结果导向说明。

解释：
明确听众收益，提升专注度，让大家知道这场分享是“可拿走可实践”的。

重点描述：
- 不是讲概念，而是讲可落地方法
- 有流程、有模板、有踩坑经验

## 第 4 页：为什么是现在
提示词：
生成一页“为什么现在要做 AI Coding”的页面。用两列对比：左侧“过去：尝鲜、偶发使用”，右侧“现在：可用、可管控、可规模化”。底部给一句结论“价值来自缩短反馈回路，而不是替代工程师”。

解释：
给出时间窗口判断，避免听众把 AI Coding 理解为短期风口。

重点描述：
- 工具成熟度提升
- 团队流程可接入
- 核心价值是效率和质量协同

## 第 5 页：结论先行
提示词：
生成一页“结论先行”页面，用三条强结论展示：1）AI 适合加速样板代码、重构、测试、文档；2）AI 不适合直接拍板核心架构与关键业务规则；3）最佳定位是结对编程搭档。视觉上突出“适合/不适合/最佳定位”。

解释：
先给判断框架，后面所有案例都围绕这三条展开。

重点描述：
- 先定边界，再谈效率
- 人负责决策，AI 负责加速

## 第 6 页：我的实践场景
提示词：
生成一页“我的实践场景”页面，展示从需求到上线的流程链路：需求理解、任务拆解、编码实现、测试回归、文档与交付。每个环节标注 AI 的主要介入点。

解释：
把 AI 放到真实研发流程中，而不是孤立演示一个对话窗口。

重点描述：
- AI 贯穿多环节
- 最大收益在“反复且可标准化”的任务

## 第 7 页：收益排序
提示词：
生成一页“AI 使用收益排序”页面，按从高到低展示四项：代码改造与重构建议、单测补全与边界提示、陌生代码阅读与问题定位、文档与 PR 描述生成。每项给出一句收益说明。

解释：
帮助同事优先从高回报场景开始试点，快速建立正反馈。

重点描述：
- 先做高收益低风险场景
- 不追求一步到位全流程 AI 化

## 第 8 页：实战案例背景
提示词：
生成一页“实战案例背景”页面。说明任务是一个真实小需求，约束包括时间有限、已有历史代码、不能破坏线上行为。页面需要有“任务目标”和“约束条件”两个模块。

解释：
先讲清边界，再开始实操，避免演示看起来像理想环境。

重点描述：
- 真实需求
- 真实约束
- 真实质量要求

## 第 9 页：实战步骤总览
提示词：
生成一页流程图页面，标题“AI Coding 实战 5 步法”：1）需求转提示词；2）先出方案再写代码；3）小步提交并持续测试；4）AI 审查风险；5）产出 PR 说明与复盘。风格清晰，适合演讲逐步讲解。

解释：
让听众先看到全图，再逐步放大每一步。

重点描述：
- 5 步法是可复用方法论
- 每一步都必须可验证

## 第 10 页：好提示词 vs 坏提示词
提示词：
生成一页对比页面，左侧“坏提示词：模糊、无约束、无验收”，右侧“好提示词：有上下文、有边界、有验收标准”。每侧提供一个简短示例，突出输出质量差异。

解释：
通过反差让大家理解：不是 AI 不行，而是输入质量决定输出质量。

重点描述：
- 提示词要包含背景、任务、约束、验收
- 模糊需求会放大返工成本

## 第 11 页：提示词模板（可直接复用）
提示词：
生成一页“提示词模板库”页面，包含三个模板卡片：需求拆解模板、最小改动实现模板、代码审查模板。每个卡片展示结构字段，不要长段文字。

解释：
给听众可立即拿走的工具，降低试点门槛。

重点描述：
- 模板化可以提升稳定性
- 团队可共建并持续迭代

## 第 12 页：常见坑
提示词：
生成一页“常见坑”页面，列出四类问题：幻觉 API、过度重构、忽略业务约束、安全与隐私风险。每类问题附一句“真实后果”。页面语气客观，不夸张。

解释：
提前打预防针，建立正确预期：AI 能提效，但不会自动保证正确。

重点描述：
- 错误通常发生在边界与隐性约束
- 看起来对不等于真的可上线

## 第 13 页：防坑清单
提示词：
生成一页“防坑清单”页面，格式为 checklist。至少包含：改动可测试、改动可回滚、关键逻辑人工 review、先查文档或源码再改、合入前跑完整质量门禁。

解释：
把经验沉淀为动作清单，避免分享结束后无法执行。

重点描述：
- 用流程对抗不确定性
- 用清单保证最低质量线

## 第 14 页：团队落地路线图
提示词：
生成一页“三层落地路线图”页面，分为个人层、小组层、团队层。个人层强调低风险试点，小组层强调模板与评审规范，团队层强调质量门禁和指标追踪。可用阶梯或路线图视觉。

解释：
告诉大家如何从个人实践走向团队机制，而不是停在个人技巧。

重点描述：
- 路线图要循序渐进
- 管理抓手是机制，不是口号

## 第 15 页：指标与成效评估
提示词：
生成一页“成效评估指标”页面，展示 Lead Time、缺陷率、返工率、评审吞吐四个指标，并附“不要只看速度，也要看稳定性”的提醒。

解释：
补齐管理视角，避免只讲体验不讲结果。

重点描述：
- 速度与质量要同时优化
- 指标用于持续改进，而非一次性汇报

## 第 16 页：总结与行动建议
提示词：
生成一页“总结与下一步”页面。上半部分三句话总结：AI Coding 是效率杠杆、价值来自人机协同流程、小步快跑和可验证是关键。下半部分给出下周可执行的 3 个行动项。

解释：
把分享收束到“可执行动作”，推动听众从听懂到开始做。

重点描述：
- 总结要短、要硬、要可执行
- 行动建议要具体到一周内

## 第 17 页：Q&A

解释：
提前准备高频问题，提升答疑质量和节奏。

重点描述：
- 回答聚焦场景和方法
- 不做泛化承诺
