## 第 10 页：Vibe Coding、Plan Mode、Spec Mode
提示词：

整体风格专业、简洁、工程化，适合企业内部技术分享。

备注：
前面讲到的是我日常 AI Coding 时的一套完整流程，但这并不意味着我每次都严格按同样的强度去执行。

很多 AI Coding 分享都会提到 Vibe Coding、Plan Mode 和 Spec Mode。

我的理解是，这三个词并不是三种完全不同的开发方式，而是同一套工作流在不同复杂度下的应用。

对于一个简单需求，比如改一个页面、修一个 Bug，我通常直接和 AI 交互实现，不会专门写 Plan 或做额外 Review，这就是 Vibe Coding。

对于日常功能开发，我会先让 AI 帮我拆任务、审 Plan，再进入实现阶段，这就是 Plan Mode，也是我最常用的方式。

而对于复杂需求、大型重构或者高风险改动，我会先明确需求、边界和验收标准，再进入规划和实现阶段，这就是 Spec Mode。

随着任务复杂度增加，我们会引入更多约束和检查机制；随着任务变简单，则会减少流程成本，提高效率。

重点描述：
- Vibe -> Plan -> Spec，本质是工程控制逐步增强
- 任务越复杂，需要的约束和验证越多
- 三者不是互斥关系，而是同一工作流的不同裁剪方式
- 我的日常开发以 Plan Mode 为主，根据任务复杂度向两侧调整流程
- 不追求固定模式，而是根据任务风险选择合适的工作方式
